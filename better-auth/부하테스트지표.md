아래는 **Autocannon의 주요 성능 지표(latencies, requests, throughput)** 의 의미와 **어떤 수치가 좋고 나쁜지를 판단하는 기준**을 설명합니다:

---

## 🟦 1. `latencies` (지연 시간, 응답 시간)

* **의미**: 요청을 보내고 응답을 받기까지 걸리는 시간 (단위: ms)
* **좋은 지표**: 낮을수록 좋습니다.
* **기준 해석**:

  * `mean`, `average`: 전체 요청의 평균 응답 시간
  * `stddev`: 표준편차 — 값이 클수록 응답 시간의 편차가 큼 → 안정성 ↓
  * `min`, `max`: 최단 / 최장 응답 시간
  * `p50` (median): 요청의 절반은 이 시간 이내에 응답 받음 → **실제 체감 속도**
  * `p90`, `p99`, `p99_9`, ...: 전체 요청 중 상위 몇 %가 이 시간보다 **느리다**

### 💡 해석 예시 (latencies)

| 기준        | 값      | 해석                |
| --------- | ------ | ----------------- |
| `average` | 2578ms | 평균 응답이 2.5초로 꽤 느림 |
| `min`     | 9ms    | 일부 요청은 빠름         |
| `p50`     | 3040ms | 절반의 요청이 3초 안에 응답  |
| `p90`     | 6063ms | 90% 요청은 6초 안에 끝남  |
| `stddev`  | 1912ms | 편차 큼 = 응답 속도 불안정  |

✅ **좋을 때**: 평균/중앙값이 낮고 `p90`/`p99`가 크게 치솟지 않음
❌ **나쁠 때**: `p50`은 낮은데 `p90`, `p99`가 높으면 지연된 요청이 많음 (불균형)

---

## 🟨 2. `requests` (초당 요청 수, RPS)

* **의미**: 초당 처리한 HTTP 요청 수
* **좋은 지표**: 높을수록 좋습니다. 서버의 처리 능력을 나타냄.
* 이 값이 클수록 많은 요청을 동시에 처리할 수 있다는 의미.

### 💡 해석 예시

| 기준    | 값    | 해석                    |
| ----- | ---- | --------------------- |
| `p50` | 800  | 절반의 순간에서 초당 800 요청 처리 |
| `p99` | 1200 | 최고 성능은 초당 1200 처리 가능  |

✅ 클수록 서버의 처리량이 높음
❌ 낮으면 병목(느림) or 처리 한계에 도달한 것

---

## 🟩 3. `throughput` (초당 전송량, Mbps 또는 Bytes/sec)

* **의미**: 초당 네트워크로 전송된 데이터 양
* **좋은 지표**: 높을수록 좋습니다 (특히 API가 큰 데이터를 전송할 경우 중요)
* 단위: 기본은 **bytes/sec**, 환경에 따라 Mbps로 환산 가능

### 💡 해석 예시

| 기준        | 값      | 해석                  |
| --------- | ------ | ------------------- |
| `average` | 128000 | 평균적으로 초당 128KB 전송   |
| `p99`     | 200000 | 최대 순간 전송량은 초당 200KB |

✅ **높고 안정적**이면 대량의 응답 데이터도 잘 처리 중
❌ **낮거나 요동치면** 느린 응답/전송 문제

---

## 📊 요약 - 어떻게 판단하나?

| 지표             | 해석 기준                         |
| -------------- | ----------------------------- |
| **latencies**  | 낮을수록 좋고, `p99`가 지나치게 높으면 불안정함 |
| **requests**   | 초당 요청 수, 클수록 서버 처리 성능 높음      |
| **throughput** | 전송량, 클수록 좋음 (대량 응답을 잘 보낸다는 뜻) |
